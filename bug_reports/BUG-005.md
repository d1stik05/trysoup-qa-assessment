# BUG-005: Missing Numeric Bounds, Boolean Guards, and Degenerate LR Checks in `SoupConfig` (`batch_size: 0` Causes `ZeroDivisionError`, `lr: 1e-30` Produces Zero Weight Update) `[Silent Acceptance / Traceback]`

## 1. Title
`[Silent Acceptance / Traceback]` `SoupConfig`, `TrainingConfig`, `DataConfig`, and `LoraConfig` accept out-of-range and degenerate values (`batch_size: 0` -> `ZeroDivisionError` in `soup doctor`, `lora.r: -8`, `lora.dropout: 5.0`, `lr: .inf`, `lr: .nan`, `epochs: true`, `base: ""`), and `lr: 1e-30` completes GPU training (`exit 0`) with `lora_B_global_l2_norm == 0.0` (100% untrained adapter).

## 2. Environment
- **Local Baseline:** Windows 11 (`10.0.26200-SP0`), Python `3.14.2`, `soup-cli==0.72.4`
- **Google Colab Target Hardware:** Linux `6.6.113+` (`x86_64`), Python `3.13.16`, `soup-cli==0.72.4`, NVIDIA Tesla T4 GPU
- **Affected Source Files:**
  - `soup_cli/config/schema.py` (`SoupConfig.base`, `DataConfig.max_length`, `TrainingConfig.batch_size`, `TrainingConfig.lr`, `LoraConfig.r`, `LoraConfig.alpha`, `LoraConfig.dropout`)
  - `soup_cli/utils/gpu.py:293` (`estimate_training_time` divides by `batch_size` without checking `batch_size > 0`)

## 3. Severity
**`High`**
**Justification:** Lack of Pydantic field constraints (`gt=0`, `ge=0.0, lt=1.0`, `allow_inf_nan=False`, `StrictInt`, `min_length=1`) allows invalid configurations to pass `soup config validate` (`exit 0`) and either crash downstream commands with unhandled Python exceptions (`ZeroDivisionError: float division by zero` in `soup doctor`) or waste GPU hours producing a completely zeroed LoRA adapter (`lora_B_global_l2_norm == 0.0` when `lr: 1e-30`).

## 4. Steps to Reproduce
1. Run `soup config validate configs/repro_bug005_schema_bounds.yaml` and observe that it prints `Config is valid!` (`exit 0`) despite `base: ""`, `max_length: 0`, `epochs: true`, `batch_size: 0`, `lr: .inf`, `lora.r: -8`, `lora.alpha: -16`, and `lora.dropout: 5.0`.
2. Run `soup --verbose doctor --config configs/repro_bug005_schema_bounds.yaml` and observe the unhandled `ZeroDivisionError: float division by zero` at `soup_cli/utils/gpu.py:293`.
3. On a Tesla T4 GPU, run `soup train` with `lr: 1e-30` (`sf_gpu3_zero_update.yaml`) and inspect `adapter_model.safetensors`.

## 5. Expected Result
1. `SoupConfig` should reject `base: ""` (`min_length=1`), boolean values for `int`/`float` fields, `batch_size <= 0`, `max_length <= 0`, `lora.r <= 0`, `lora.alpha <= 0`, `lora.dropout < 0 or >= 1`, and non-finite `lr` (`allow_inf_nan=False`, `gt=1e-12`).
2. Post-training verification in `soup train` should warn or fail if all `lora_B` weights remain exact zeros (`norm == 0.0`) after training completes.

## 6. Actual Result
- **Classification:** `Silent Acceptance` (`exit 0` in `soup config validate` and `soup train` with `lr: 1e-30`) and `Traceback` (`ZeroDivisionError` in `soup doctor` when `batch_size: 0`).
- On Colab T4 (`run_20261111_112150_89e897ba`), `lr: 1e-30` runs 15 steps, prints `Training Complete!`, exits `0`, and writes `adapter_model.safetensors` with **`lora_B_global_l2_norm: 0.0`**.
