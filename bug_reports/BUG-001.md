# BUG-001: Pydantic Config Schemas (`SoupConfig`, `TrainingConfig`, `DataConfig`, `LoraConfig`) Lack `extra="forbid"`, Silently Ignoring Misspelled & Alias Hyperparameters `[Silent Acceptance]`

## 1. Title
`[Silent Acceptance]` `soup config validate` and `soup train` silently ignore misspelled YAML keys (`epchs`, `lora_r`, `taks`) and standard HuggingFace hyperparameter aliases (`learning_rate`, `max_steps`, `num_train_epochs`, `seed`), exiting with code `0` and training with unintended default parameters.

## 2. Environment
- **Local Baseline:** Windows 11 (`10.0.26200-SP0`), Python `3.14.2`, `soup-cli==0.72.4`, `pydantic==2.12.5`, `pytest==9.2.0`, `hypothesis==6.170.15`, `torch==2.15.0+cpu`
- **Google Colab Target Hardware:** Linux `6.6.113+` (`x86_64`), Python `3.13.16`, `soup-cli==0.72.4`, `torch==2.14.1+cu130`, NVIDIA Tesla T4 GPU (`15,360 MiB`, `cc=7.5`)
- **Affected Source File:** `soup_cli/config/schema.py` (`SoupConfig`, `DataConfig`, `TrainingConfig`, `LoraConfig`, `EvalConfig`)

## 3. Severity
**`Critical`**
**Justification:** Silent hyperparameter replacement directly corrupts ML experiments without warning. A user who writes `learning_rate: 0.0` (instead of `lr:`), `epchs: 99` (instead of `epochs:`), or `lora_r: 4` (instead of `lora.r:`) receives `"Config is valid!"` and `"Training Complete!"` (`exit 0`), while `soup-cli` secretly trains for 3 epochs at `lr=2e-5` with `lora.r=64` (16x the intended adapter parameter count).

## 4. Steps to Reproduce
1. Create [`../configs/repro_bug001_typos.yaml`](../configs/repro_bug001_typos.yaml) containing misspelled keys (`taks`, `epchs`, `lora_r`) and HuggingFace aliases (`learning_rate: 0.0`, `max_steps: 2`).
2. Run `soup config validate configs/repro_bug001_typos.yaml`.
3. Run `soup train --config configs/repro_bug001_typos.yaml --allow-oom-attempt --yes` on a Tesla T4 GPU.
4. Inspect the exit code, printed summary table, and step-1 logged learning rate.

## 5. Expected Result
`SoupConfig` and all nested Pydantic models (`DataConfig`, `TrainingConfig`, `LoraConfig`, `EvalConfig`) should enforce `model_config = ConfigDict(extra="forbid")` and exit with code `1` (`ValidationError: Extra inputs are not permitted`), listing every unrecognized or misspelled key (`taks`, `learning_rate`, `epchs`, `lora_r`, `max_steps`).

## 6. Actual Result
- **Classification:** `Silent Acceptance` (`exit_code = 0`)
- `soup config validate` prints `Config is valid!` and displays a summary table with default values (`Epochs: 3`, `LoRA r: 64`, `LR: 2e-05`).
- On Google Colab Tesla T4 GPU (`run_20261111_112103_9939e658`), `soup train` prints `LoRA: r=64, alpha=16`, `LoRA applied: 8,192 trainable`, executes 15 steps (3 epochs) at `learning_rate: 2e-05`, prints `Training Complete!`, and exits with code `0`.

## 7. Minimal Reproducing Example
**Command:**
```bash
soup config validate configs/repro_bug001_typos.yaml
soup train --config configs/repro_bug001_typos.yaml --allow-oom-attempt --yes
```

**Minimal YAML ([`../configs/repro_bug001_typos.yaml`](../configs/repro_bug001_typos.yaml)):**
```yaml
base: trl-internal-testing/tiny-random-LlamaForCausalLM
task: sft
taks: invalid_typo_ignored
data:
  train: configs/sample_train.jsonl
  format: chatml
  chat_template: chatml
training:
  learning_rate: 0.0
  epchs: 99
  lora_r: 4
  max_steps: 2
  auto_mixed_precision: true
output: ./output_bug001
```
