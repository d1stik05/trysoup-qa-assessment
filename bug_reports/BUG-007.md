# BUG-007: False-Positive Hardware-Fit VRAM Gate Blocks `<10 MB` Models on 16 GB Tesla T4 GPUs (`model_size_from_name` Defaults to `7.0`B = 14 GB), and `_resolve_mixed_precision` Defaults to `bf16=True` on T4 `[Clear Error / Hardware Gate Defect]`

## 1. Title
`[Hardware Gate Defect]` `soup train` and `soup train --dry-run` block `<10 MB` models (`trl-internal-testing/tiny-random-LlamaForCausalLM`, 1.03M params) on a 15.6 GB NVIDIA Tesla T4 GPU (`exit 1`) because `model_size_from_name()` defaults to `7.0` billion parameters (`14.0 GB` weights) for any model ID lacking an `Nb`/`Nm` regex match; additionally, `SFTTrainerWrapper._resolve_mixed_precision()` sets `bf16=True` whenever `auto_mixed_precision=False` (the default), ignoring Turing (`cc=7.5`) hardware capabilities.

## 2. Environment
- **Google Colab Target Hardware:** Linux `6.6.113+` (`x86_64`), Python `3.13.16`, `soup-cli==0.72.4`, `torch==2.14.1+cu130`, NVIDIA Tesla T4 GPU (`15,360 MiB`, `cc=7.5`)
- **Affected Source Files:**
  - `soup_cli/utils/gpu.py:213` (`model_size_from_name` returns `7.0` when regex fails to find a size token in the model name)
  - `soup_cli/commands/train.py:1345-1368` (Hardware-Fit gate blocks launch with `rc=1` unless `--allow-oom-attempt` is passed)
  - `soup_cli/trainer/sft.py:165-185` (`_resolve_mixed_precision` returns `(self.device == "cuda", False)` when `auto_mixed_precision` is `False`)

## 3. Severity
**`High`**
**Justification:** Breaks out-of-the-box execution on Google Colab Tesla T4 (`16 GB` VRAM) for any custom, fine-tuned, local-path, or HuggingFace Hub model whose repository name does not explicitly contain a substring like `"1b"`, `"3b"`, or `"125m"`. Even a 4 MB test model (`1,033,296` total parameters) is rejected with `Predicted peak VRAM 16.2 GB (+10% margin = 17.8 GB) exceeds 15.6 GB available`. Furthermore, `TrainingConfig.auto_mixed_precision` defaults to `False`, which causes `_resolve_mixed_precision()` to request `bf16=True` on all CUDA devices without checking `torch.cuda.get_device_capability()[0] >= 8`.

## 4. Steps to Reproduce
1. On a Google Colab NVIDIA Tesla T4 GPU (`15.6 GB` available VRAM), run `soup train --config configs/repro_bug007_hw_gate.yaml --yes` (without `--allow-oom-attempt`).
2. Observe that `soup train` immediately exits with code `1` at the `Hardware-fit gate`, claiming `weights 14.0 GB` and `Predicted peak VRAM 16.2 GB (+10% margin = 17.8 GB) exceeds 15.6 GB available`.
3. Re-run with `--allow-oom-attempt` and observe that actual model parameter count is `1,033,296 total` (~4 MB).

## 5. Expected Result
1. When estimating VRAM for a HuggingFace Hub or local model whose name does not match the `Nb`/`Nm` regex, `estimate_vram()` should inspect `AutoConfig.from_pretrained()` (or local safetensors file size) before assuming a 7B (`14.0 GB`) model, or downgrade unparsed names to a non-blocking warning.
2. `SFTTrainerWrapper._resolve_mixed_precision()` should check `torch.cuda.is_bf16_supported()` (or `cc >= 8.0`) and fall back to `fp16=True` on Tesla T4 (`cc=7.5`) even when `auto_mixed_precision` is not explicitly enabled.

## 6. Actual Result
- **Classification:** `Clear Error` (False-Positive Hardware Gate Block, `exit_code = 1`)
- Without `--allow-oom-attempt`, both `soup train` and `soup train --dry-run` abort before loading the dataset or model on a 16 GB Tesla T4 GPU.
