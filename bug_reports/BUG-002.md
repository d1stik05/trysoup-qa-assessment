# BUG-002: Missing `TrainingConfig.seed` Field and Unseeded LoRA Initialization Before `TrainingArguments` Cause $L_2 = 4.73$ Adapter Weight Divergence and Empty `--repro-receipt` `[Silent Acceptance]`

## 1. Title
`[Silent Acceptance]` `TrainingConfig` omits a `seed` field and `SFTTrainerWrapper.setup()` initializes LoRA (`get_peft_model`) before `TrainingArguments` sets the random seed—causing `training.seed` to be silently ignored, `--repro-receipt` to emit `"seeds": {}`, and `lora_A` weights to diverge by $\|\theta_1 - \theta_2\|_2 = 4.7295$ across identical runs.

## 2. Environment
- **Google Colab Target Hardware:** Linux `6.6.113+` (`x86_64`), Python `3.13.16`, `soup-cli==0.72.4`, `torch==2.14.1+cu130`, `CUDA 13.0`, `cuDNN 92800`, NVIDIA Tesla T4 GPU (`15,360 MiB`, `cc=7.5`)
- **Local Baseline:** Windows 11 (`10.0.26200-SP0`), Python `3.14.2`, `soup-cli==0.72.4`, `torch==2.15.0+cpu`
- **Affected Source Files:**
  - `soup_cli/config/schema.py:2875` (`TrainingConfig` lacks `seed: Optional[int] = 42`)
  - `soup_cli/trainer/sft.py:219, 471, 585, 949` (`_setup_transformers` calls `get_peft_model` before `TrainingArguments` sets the seed, and never passes `seed` into `training_kwargs`)
  - `soup_cli/commands/train.py:1668` (`_write_repro_receipt` reads `getattr(cfg.training, "seed", None)` which is always `None`)

## 3. Severity
**`Critical`**
**Justification:** Completely breaks model weight reproducibility and invalidates the SR 11-7 regulatory compliance feature (`--repro-receipt`). Every run initializes `lora_A` with unseeded OS entropy before `TrainingArguments` sets `seed=42`, producing orthogonal `lora_A` projection matrices ($\|A_1 - A_2\|_2 \approx 2.33$ per layer, $4.73$ globally) and writing an empty `"seeds": {}` object to `repro_receipt.json`.

## 4. Steps to Reproduce
1. Run `soup train --config configs/repro_bug002_seed.yaml --allow-oom-attempt --yes` twice on a Tesla T4 GPU (`exp1a_run1` and `exp1a_run2`).
2. Run a third time with `training.seed: 999` and `--repro-receipt` (`exp1b`).
3. Compute the $L_2$ norm of the weight difference $\|\theta_1 - \theta_2\|_2$ across the saved `adapter_model.safetensors` files and inspect `repro_receipt.json`.

## 5. Expected Result
1. `TrainingConfig` should declare `seed: int = 42`.
2. `SFTTrainerWrapper.setup()` should call `transformers.set_seed(tcfg.seed)` **before** loading the model or calling `get_peft_model()`, and pass `seed=tcfg.seed` to `TrainingArguments`.
3. Two runs with `seed: 42` should initialize identical `lora_A` weights ($\|\theta_1 - \theta_2\|_2 \le 10^{-2}$ on GPU, `0.0` on CPU), and `--repro-receipt` should record `{"seeds": {"training": 999}}`.

## 6. Actual Result
- **Classification:** `Silent Acceptance` (`exit_code = 0`)
- **Identical Seed Runs (`seed=42` vs `seed=42`):** Step-1 loss is identical (`10.3557`) because `lora_B` starts at zero and `TrainingArguments` seeds the DataLoader at line 471, **after** `get_peft_model()` at line 949. However, `lora_A` was initialized unseeded, causing a **Global Adapter $L_2$ Diff of `4.729505`** (`max_abs_diff = 0.461653`).
- **Different Seed Run (`seed=999` + `--repro-receipt`):** `training.seed: 999` is ignored, `repro_receipt.json` contains `"seeds": {}`, and the adapter $L_2$ diff vs `seed=42` (`4.625596`) is indistinguishable from the identical-seed run (`4.729505`).
