# BUG-004: `soup data validate` and `soup train --dry-run` Exit with Code `0` (`"Data OK: 0 train samples"`) on Empty, 100% Corrupted, or Column-Mismatched Datasets `[Silent Acceptance]`

## 1. Title
`[Silent Acceptance]` `soup data validate` and `soup train --dry-run` exit with status `0` (`"Data OK: 0 train samples"`, `"Config valid. Ready to train!"`) when given a 0-byte file, a JSONL where 100% of rows fail JSON parsing, a dataset whose columns do not match `data.format`, or a 1-row dataset truncated to `0` train samples by `val_split`.

## 2. Environment
- **Local Baseline:** Windows 11 (`10.0.26200-SP0`), Python `3.14.2`, `soup-cli==0.72.4`
- **Google Colab Target Hardware:** Linux `6.6.113+` (`x86_64`), Python `3.13.16`, `soup-cli==0.72.4`, NVIDIA Tesla T4 GPU
- **Affected Source Files:**
  - `soup_cli/data/loader.py:182` (`load_raw_data` silently skips malformed JSON lines and returns `[]`)
  - `soup_cli/data/validator.py` & `soup_cli/commands/data.py` (`soup data validate` exits `0` when `valid_rows == 0`)
  - `soup_cli/commands/train.py:1370-1405` (`--dry-run` prints `Data OK: 0 train samples` and exits `0`)

## 3. Severity
**`High`**
**Justification:** Users and CI pipelines rely on `soup data validate` and `soup train --dry-run` as pre-flight checks before provisioning GPU instances. Because `--dry-run` exits `0` on `0 train samples` and skips tokenizer `chat_template` validation, the failure is deferred until full GPU training downloads the model, allocates VRAM, and crashes with an unhandled `ValueError: Column name ['messages'] not in the dataset. Current columns in the dataset: []`.

## 4. Steps to Reproduce
1. Run `soup train --config configs/repro_bug004_zero_samples.yaml --dry-run` (where [`../configs/sample_mismatched_cols.jsonl`](../configs/sample_mismatched_cols.jsonl) contains `{"question": "...", "answer": "..."}` rows instead of `messages` required by `format: chatml`).
2. Observe that `--dry-run` prints `Data OK: 0 train samples` and `Config valid. Ready to train!` with exit code `0`.
3. Now run full training (`soup --verbose train --config configs/repro_bug004_zero_samples.yaml --allow-oom-attempt --yes`) and observe the crash after model loading.

## 5. Expected Result
1. `soup data validate` must exit non-zero (`exit 1`) if `total_rows == 0` or `valid_rows == 0`.
2. `load_dataset()` and `soup train --dry-run` must exit non-zero (`exit 1`) with a clear error message whenever `len(dataset["train"]) == 0`.

## 6. Actual Result
- **Classification:** `Silent Acceptance` (`exit_code = 0` on `soup data validate` and `soup train --dry-run`), followed by `Traceback` (`ValueError`) during full `soup train`.
- `--dry-run` outputs `Data OK: 0 train samples` and `Config valid. Ready to train!` (`exit 0`).
- Full `soup train` prints `Loaded: 0 train samples`, loads the model and LoRA onto the Tesla T4 GPU, and then crashes at `soup_cli/trainer/sft.py:342` with `ValueError: Column name ['messages'] not in the dataset. Current columns in the dataset: []`.

## 7. Minimal Reproducing Example
**Command:**
```bash
soup train --config configs/repro_bug004_zero_samples.yaml --dry-run
soup --verbose train --config configs/repro_bug004_zero_samples.yaml --allow-oom-attempt --yes
```

**Minimal YAML ([`../configs/repro_bug004_zero_samples.yaml`](../configs/repro_bug004_zero_samples.yaml)):**

