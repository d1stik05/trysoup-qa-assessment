# BUG-003: `SoupTrainerCallback` Loss Watchdog Fails to Detect `NaN` Loss, and When Triggered by Exploding Loss (`lr: 1e15`), `soup train` Still Prints `"Training Complete!"` and Exits `0` `[Silent Acceptance]`

## 1. Title
`[Silent Acceptance]` `SoupTrainerCallback.on_log` fails on three counts: (1) `float('nan') > watchdog_threshold` evaluates to `False` so `NaN` losses never trigger the watchdog; (2) when the watchdog *does* halt training on an exploding loss (`lr: 1e15`, weights exploded to $2.26 \times 10^{16}$), `soup train` marks the run `"completed"`, prints `"Training Complete!"`, and exits with code `0`; and (3) the final summary log overwrites step-15 telemetry with `loss: 0.0, lr: 0.0, GPU: 0.0 GB`.

## 2. Environment
- **Google Colab Target Hardware:** Linux `6.6.113+` (`x86_64`), Python `3.13.16`, `soup-cli==0.72.4`, `torch==2.14.1+cu130`, NVIDIA Tesla T4 GPU (`15,360 MiB`, `cc=7.5`)
- **Local Baseline:** Windows 11 (`10.0.26200-SP0`), Python `3.14.2`, `soup-cli==0.72.4`
- **Affected Source Files:**
  - `soup_cli/monitoring/callback.py:212-255` (`SoupTrainerCallback.on_log`)
  - `soup_cli/commands/train.py:1418-1450` (`train` command completion handling)

## 3. Severity
**`Critical`**
**Justification:** The `loss_watchdog` is explicitly designed as a safety mechanism to abort diverged training runs. However, (a) if loss overflows to `NaN`, IEEE 754 `nan > threshold` is `False`, so the watchdog resets `_watchdog_counter = 0` and never stops training; and (b) when the watchdog *does* stop training at Step 1/15 (`7%`) with weights exploded to $2.26 \times 10^{16}$, `soup train` saves the corrupted checkpoint and exits `0`, causing CI/CD pipelines to promote a destroyed model into production.

## 4. Steps to Reproduce
1. **GPU Watchdog Abort Exit-`0` Reproduction:** Run `soup train --config configs/repro_bug003_watchdog.yaml --allow-oom-attempt --yes` on a Tesla T4 GPU (`lr: 1e15`, `loss_watchdog: true`, `loss_watchdog_threshold: 3.0`, `loss_watchdog_patience: 1`).
2. Observe that the watchdog triggers at Step 1/15, yet `soup train` prints `Training Complete!`, saves the exploded adapter (`lora_B_global_l2_norm = 2.26e16`), and exits with code `0`.
3. **Local `NaN` Blindness Reproduction:** Run `pytest tests/test_silent_failures.py -k test_sf06_loss_watchdog_ignores_nan_loss_due_to_ieee754_comparison`.

## 5. Expected Result
1. `SoupTrainerCallback.on_log` should check `if math.isnan(loss) or math.isinf(loss) or loss > self.watchdog_threshold:`.
2. When `loss_watchdog` halts training early, `soup train` should mark the SQLite run status as `"failed"` (or `"aborted_by_watchdog"`), refuse to print `"Training Complete!"`, and exit with non-zero status (`exit 1`).
3. `SoupTrainerCallback.on_log` should ignore HF Trainer's final summary dict when `'loss'` is not in `logs` (`if "loss" not in logs: return`), instead of logging a phantom `loss: 0.0` entry.

## 6. Actual Result
- **Classification:** `Silent Acceptance` (`exit_code = 0`)
- On Colab T4 (`run_20261111_112127_99d38e4b`), the watchdog aborts training at Step 1/15 (`Epoch 0.2/3`), saves adapter weights with `lora_B_global_l2_norm = 2.2604958881415044e+16`, records `"status": "completed"` in SQLite, prints `Training Complete!`, and exits `0`.
- On local unit probe (`SF-06`), 5 consecutive steps of `loss: float("nan")` result in `_watchdog_counter == 0` and `should_training_stop == False`.
